# Vaal Street

A local trading desk for the Path of Exile Currency Exchange. It mirrors the exchange's public hourly history, turns it into prices you can trust, and answers the questions a trader actually has: what is this worth, what can I flip right now, what converts into something dearer, what did this item do at this point of past leagues, and would my strategy have made money.

Everything runs on your machine. The only network traffic is read-only requests for the public exchange digests, an item-name export, item icons and, unless you turn it off, poe.ninja's public price lists for the few card rewards the exchange does not trade (at most once an hour per list). Every request names this project and its address, and nothing about you is sent. No account, no tokens, no in-game automation. The optional screen check reads your screen once per key press and sends nothing to the game; if you turn on its stack check, it also reads the clipboard once each time you press the game's copy key.

PoE 1 is the focus. The data layer also mirrors PoE 2, but the desk and models are built and tested against PoE 1.

## Quick start

Requires Python 3.10+.

```sh
pip install -e .
python -m vaalstreet serve
```

Open **http://localhost:3000**. On first launch the desk downloads the last two weeks of exchange hours (a couple of minutes) and then keeps itself current, one new hour every hour. A short tour walks you through the pages on your first visit; press `?` or click "tour of the desk" at the bottom of the menu to see it again.

To compare leagues you need more history. Either press **Download full history** on the League start page, or run:

```sh
python -m vaalstreet sync --all      # every hour since July 2024, newest first, resumable (~1.5 GB)
```

## Windows app

On Windows, the desk, its hideout window and the screen check can run as one app next to the game, with nothing to start in WSL or in a console.

The app is a window around the same desk. Starting it starts the desk and the screen check together (the `app` command under "Command line"), and quitting it stops both. The page inside is the one a browser shows. **Hideout** (press `H`, or Ctrl+H from the menu) opens as a window of the app that stays on top of other windows, the game included when it runs in windowed or borderless windowed mode. The screen check's keys work as they do for the companion: Ctrl+Alt+F9 reads the offer on screen, and Ctrl+Alt+F10 also records it. The stack check stays off until you tick it under **Screen check** in the menu; a second tick there also writes each copied stack to your stash list. Ticking either starts the desk again. **Desk → What the desk last said…** shows the last lines the desk and the screen check printed, which is where to look when a key seems to do nothing. A link that leaves the desk opens in your normal browser. Starting the app a second time shows the one already running, so two desks never write to one ledger.

**Install.** Download `VaalStreet-Setup-<version>.exe` from the project's Releases page on GitHub and run it. It installs for your Windows user only and needs no administrator rights, no Python and no Node.js: the desk, the screen check and its text recognition are inside. The installer is not signed, so Windows SmartScreen may warn about an unknown publisher; choose "More info", then "Run anyway". If you run the game as administrator, run the app as administrator too, or Windows hides your key presses from the screen check.

**Where the data lives.** The app keeps its archive and your ledger in `C:\Users\<you>\.vaalstreet`, the same place an installed package uses (`VAAL_DATA_DIR` names another). **Desk → Open the data folder** shows it. On a first start with no data, the app downloads the last two weeks, as the desk always does.

**Bringing your data over from WSL.** A desk you ran in WSL keeps its data inside WSL, in `data/` in the checkout. The app does not read it there: Windows reaches WSL files slowly, and a ledger file used across that boundary can be damaged. Copy it once instead. Stop the desk in WSL, quit the app, and run in WSL, from the checkout:

```sh
mkdir -p /mnt/c/Users/<you>/.vaalstreet
cp -a data/. /mnt/c/Users/<you>/.vaalstreet/
```

This copies the archive (about 1.5 GB with the full history), your ledger `desk.sqlite`, your strategies and the item icons, and changes nothing in WSL. From then on the Windows copy is the one that counts: record trades in the app only, because the two ledgers are separate files and nothing merges them. The WSL copy stays as a backup of the day you copied.

The app uses port 3917 on your own machine (the next free one up to 3926 if it is taken), not 3000, so a desk running in WSL does not get in its way. The app itself adds no network traffic: it opens only the local desk.

To run the app from a checkout on Windows, you need Python 3.10 to 3.12 with the package and its screen check libraries installed (see "Screen check (optional)"), and Node.js 20 or later:

```
cd desktop
npm install
npm start
```

`VAAL_PYTHON` names the Python to use if it is not the `python` on your PATH.

The installer is built by GitHub Actions on a Windows machine (`.github/workflows/windows-app.yml`), for every version tag and on request. It freezes the Python side with PyInstaller into `vaal-desk.exe`, checks that this program starts, serves the page, starts the screen check and stops, and then packs it with the window into the installer. `vaal-desk.exe` is the whole command line: `vaal-desk.exe sync --all`, for example, works from a console in the app's `resources\vaal-desk` folder.

Post it in game, then press Record. If you close the offer, the buy order keeps a "Sell order posted…" button for as long as you hold items no sell order offers; when you hold too few for one sell order, the desk says so instead. ## How the numbers are made

**The data.** For every market (pair of items), league and hour, the exchange publishes the volume traded on each side, the lowest and highest executed ratio, and the lowest and highest stock on offer. There is no order book and no individual trades. An item usually has two markets that matter: against Chaos and against Divine.

**Prices.** The hourly price of a market is its volume-weighted average (Chaos paid ÷ items received). Divine-market prices are converted at that same hour's Divine price. The two markets of an item are kept apart, because they are not the same price: the Divine market is usually dearer, and often by a lot. Measured on 293 items in the first week of Covens, the Divine market's price was a median 16% above the Chaos market's; a quarter of items paid 69% or more through Divines, one in twenty paid nearly four times as much, and one in twenty paid 16% less. The gap is small for dear items (median 5% above 100 Chaos) and large for cheap ones (a median 25% to 45% below 10 Chaos). The published lowest/highest ratios are not used to set levels — single-unit rounding and joke trades (a Divine for one Chaos) pollute them in most hours.

**Fair value.** A local-level Kalman filter on log price per item. The item's own returns are split into real movement and bounce (negative lag-one autocovariance), hours that traded more value count for more, and prints far outside the forecast are down-weighted. A print very far out is set aside until the next print confirms it, and only an hour that traded at least half its usual number of items can confirm it: two thin hours of joke trades in a row do not move the value. Parameters are re-fitted on trailing data only, so the series is causal: the value shown for an hour used nothing from after it.

You can check the model on any league: `python -m vaalstreet scorecard --league Mirage` compares fair value with the latest print as a predictor of where the item trades over the following six hours.

**Fair value range.** The desk keeps a range around each fair value, from one standard deviation below to one above. It says how sure the model is of the value *right now*: narrow for an item that trades steadily every hour, wide for a thin or jumpy one, and wider while an item does not trade. Like fair value, the range at an hour uses nothing from after it. It is not a forecast. Prices keep moving, so later prices often land outside it, and most often for busy items, whose range is narrowest. Measured on two months of real hours (the first week of a challenge league, and Standard), the next hour's price fell inside the range about one time in five for the 50 most traded items of the new league and a bit under half the time in Standard, and the next six hours' average price one time in ten and about half the time.

**Experiment: one value per item.** `python -m vaalstreet scorecard --two-market` tries a different model. Instead of pricing the Chaos market and the Divine market separately, it fits one value per item plus how much more the Divine market pays, a gap that changes only slowly. Prints from both markets then inform the same value, which helps most when one market trades only now and then. The table compares it with each market's own fair value, the blended fair value and the last print. The desk does not use this model yet.

**Profit per hour.** Flips, conversions and round trips are all measured in profit per hour of market time, so they can be compared: the margin, times what the plan can take from the trade in an hour at your share of it. A margin alone says nothing about size: +1,000% on one Divine's worth a day is a few Chaos an hour. The switch at the top of the page shows these figures in Chaos or in Divines. A plan's last week is a return on a 1,000 Chaos stake, and next to it the desk says what that is per hour on the stake: "+160%" of 1,000 Chaos over a week is 10 Chaos an hour. That rate is not the plan's estimate. The estimate assumes as much capital as the plan's markets absorb, which for a deep market is hundreds of times the stake. Backtest results show Chaos per hour and Chaos per hour against holding Divines, always in the Chaos of the league they ran on.

**Flip plans.** For each item and pair of markets, the desk looks at where each market's *hourly average* has traded relative to fair value over the last two days. A plan buys at the level below which a given share of the buy market's volume traded, and sells at the level above which the same share of the sell market's volume traded — levels real volume went through, weighted so that an hour in which three units changed hands at a silly ratio cannot set them, and never more than about 1.5× from the fair value of *that market*: a cheap item's Divine market can trade at three times its Chaos market, so each market's levels are bounded around its own price. Three kinds: within the Chaos market, within the Divine market, and **Chaos → Divine**, which buys from players dumping loot for Chaos and sells to players paying Divines. Where an item's Divine market pays more than three times its Chaos market, as it does for some cheap items, the Chaos → Divine plan stays on the board with a warning ("the Divine market pays 6x the Chaos market here; it fills rarely"): those trades are real, but few, and such plans promise the most and replay the worst. A session plan takes one only if its last week, at its stake, beat holding Divines, like any other plan. The patience level with the highest expected profit is kept. Orders are given as whole-number ratios the exchange accepts. Expected profit per hour is the margin on the units the plan can take from the flow, or, with a bankroll, on the stake turned over once per buy and sell, whichever is smaller. One buy and sell takes as long as it took, over the last two days, for an hour's average to reach the buy level and then one to reach the sell level: often 5 to 15 hours, not one or two.

**Whole lots.** An order fills in multiples of its ratio: "7 Chaos for 3" fills three items at a time, and "1 Divine for 40" forty. The desk posts each level as the smallest ratio within 2% of it. The levels come from hourly averages, which move a median 3% to 12% within an hour or two (over two weeks of Covens; more for cheap items and in the Chaos market), so a closer ratio buys no real precision and only makes the lots bigger: 2.3 Chaos is posted as "7 for 3", not "23 for 10". Backtests with whole lots post the same orders, and so does the replay of each session-plan pick at its stake (below); the 1,000 Chaos replay every plan shows fills fractions of an item at the level. Near a whole number the lot has to grow (1.15 Chaos is "7 for 6"), and a cheap item's Divine market takes one Divine for many items whatever the ratio. The prices, margin and profit a plan shows are the ones its orders state. The patience level is still chosen at the level itself, and the level must clear the minimum margin too, so a level whose orders happen to round in your favour does not win on that. A plan's lot is the item count of the bigger of its two orders, and each plan shows how long your share of the trade takes to fill one ("One lot every"), counted the same way as in the session plan. A price level that needs more than two days for one lot is not offered: the levels are read off the last two days, and your share of what traded there would not have made a single lot. The desk then looks at the more patient levels, which sit closer to fair value and trade more. A plan that needs longer than a six-hour sitting stays on the board marked "slow", with what its thinner market traded in the last day ("its Divine market traded about 51 Divines in the last day"). A cheap item's Divine market is often a few single-Divine purchases an hour, at a price far above its Chaos market. The margin then looks huge, and the profit per hour is the number that says how little there is to take. A one-off check, on eight snapshots twelve hours apart of each of Covens, Allflame and Mirage, with a lot counted as one item or one unit of the currency, found this: where one lot took under an hour, the plan's share of the next two days' trade at its levels made at least one lot 74% to 75% of the time; at 24 to 48 hours, 26% to 30%; past 48 hours, at most 14%. This counts what the markets traded, not your fills. The exchange does not publish at what prices the stock on offer rests, so the line ahead of you is shown ("Offer queue") but not counted in a plan's speed.

Each plan also shows its own last week: the same rule, at the same patience, replayed through the backtest simulator on a 1,000 Chaos stake, with re-posted orders every 4 hours. Its orders wait in line behind the stock already on offer, as in the backtest's queue model below. The result is shown as a return and as Chaos per hour on that stake. Its return is shown next to what simply holding Divines made over the same hours, and the return against Divines is the one that counts: at a league start the Divine rises fast (+40% from day 2 to day 7 of Covens), so a flip that makes +60% in Chaos has made much less than it looks. Expect the expected profit to run well ahead of the replay. Levels read off two busy days are wider than the market keeps offering, and on Covens the session plans of the bankroll ladder made, in Chaos, between 3% and 26% of what they promised (2% to 18% against Divines) on day 8, the least at purses under 200 Chaos. Enter your bankroll and the page assembles a session plan, with each pick's last-week rate at its stake next to its promise, from the plans that sold at least twice that week and, at the stake they would get, beat holding Divines. Each item gets a quarter of the bankroll. A plan whose single lot costs more than a quarter is taken only if its markets, at your share of their volume, fill one lot within 6 hours; its stake is then that one lot, and it says so: "one lot is 40% of your purse". A single Omen worth most of a 3,000 Chaos purse, in a market that sells one every 20 hours, is left out.

**Share of the flow.** How fast a plan fills depends on how much of the market's volume at your price comes to you. The desk assumes 10% until it has your own orders to learn from. For each order you track, it counts the units that traded at or beyond your price while the order stood (for a Divine-market order, at that hour's Divine price) and compares them with what you recorded as filled. An item's measured share is all its filled units divided by all those traded units, separately for its Chaos and Divine markets. An order still open counts once it has stood three hours or filled something. An order that filled completely may have been able to take more, so it can only pull the estimate down: the desk errs on the slow side. An order can also fill on single trades in an hour whose average price never reached yours; then the measured share can come out above 100%, and the desk counts it as 100%, because no plan can take more than the whole flow. A few orders are a noisy guide, so the share a plan uses leans toward 10% as if 10% were three orders of its own: one order moves it a quarter of the way to what you measured, ten orders about three quarters. A plan uses the smaller share of its buy and sell markets, since the slower side sets the pace, and says where its share came from ("your fills, 4 orders" or "default 10%"). Only orders and fills up to the latest published hour count. `python -m vaalstreet fills` lists what your orders measured.

**Gold and time per plan.** Every order costs Gold for each item it buys or sells. For each item the desk uses the Gold per item you paid in your recorded trades and orders; if you have none for it, the fee you entered as your assumption on the Flips page; otherwise it says "Gold unknown" and leaves the Gold figures empty (the plan stays on the board). A flip buys and sells every unit, so it costs twice the fee per unit; Chaos per 1,000 Gold = 1,000 × (sell price − buy price) ÷ (2 × fee), and Gold per hour is that Gold at the units per hour the plan expects. A conversion pays the fee on every input bought and every result sold (Chaos needs no order on either side); a recipe of your own with several inputs pays for each. A round trip pays it on the first item bought, on each item given up in a swap (a Divine stop is an order like any other), and on the last item sold. A swap with a vendor is not an exchange order and costs no Gold, and Chaos you hand to a vendor never had to be bought. The game does not say what a swap costs, so the desk assumes it costs the fee of the item you give, as if you sold it. If any item on the path has no fee, the trip's Gold is unknown.

Each plan also counts the orders you post: two for a flip, one or two for a conversion, one more than the number of items for a round trip. Minutes = orders × minutes per order, a setting that starts at 1 and is your own guess. "Per hour of your time" assumes you post one batch of orders for each hour the market runs: it is profit per hour × 60 ÷ minutes.

**Re-posting an order.** When the Ledger says to re-price an order, you cancel it in game and post it again at the new ratio. The order's row then has a "Re-posted…" button that records both steps at once: it opens a small form with the plan's new ratio and the items still open filled in, and you change them to what you really posted. Recording it marks the old order as cancelled and records the new one in its place, linked to the old one, so the desk knows they are the same listing. If the new order cannot be recorded (a ratio of zero, say), the old one stays as it was. Only an order still on the exchange can be re-posted. The Gold you paid for the old order is not refunded, so the new one costs its Gold again; type it in to keep the count right.

**How long an order has stood.** The Orders table has an Age column: how long each order has stood at its ratio. Click its heading to put the oldest first. For an order you re-posted, it also says how long the item has been listed in all, counted from the first order you re-posted into this one. Ages use the desk's own clock, so in a rehearsal they count practice hours. A re-posted order also shows its earlier ratios in order, such as "9 for 4 → 7 for 3 → now 2 for 1", and the Gold you paid to post every one of them ("Gold on posting: 1,200 in all"), because Gold is not refunded when you cancel. When some posting has no Gold recorded, the sum says "at least".

**Fills the desk proposes.** The desk cannot see your fills, but it can guess them the way it measures your share of the flow (see "Share of the flow" above). For each order still on the exchange it counts the items that traded at or beyond your price in the hours since you posted it, takes the share of that flow it uses for the item and market (measured from your own orders where you have some, otherwise the share you set on the Flips page, 10% unless you change it), and keeps that within the order's size and in whole lots, rounded down: "7 Chaos for 3" fills three at a time. What you already recorded is taken off. If anything is left, the order's Filled column says so quietly ("about 12 more may have filled: check in game"), and the Filled… button starts from that number instead of everything still open. Nothing is recorded until you confirm it. The guess counts only hours the exchange has published, so it is one to two hours behind the game. The share behind a guess is measured only from orders you have settled: filled, cancelled or collected. An order you re-posted counts with the order that replaced it, once that one is settled. An order still on the exchange may have fills you have not recorded yet, and counting it as one that took nothing would shrink the very guess that asks you to record them.

Enter **Gold to spend this session** and the session plan takes plans by Chaos per 1,000 Gold instead. Gold is paid when an order is posted, so each plan counts against the budget the Gold to post its buy and sell orders once at the size of its stake: the units the stake buys, times the fee, for each side. Plans are added until the budget is spent; a stake the Gold left cannot fully pay for is shrunk, and dropped if not even one lot fits. Gold per hour stays on each plan as extra information. Plans whose Gold is unknown are not ranked: they are listed under "Gold unknown".

**Conversions.** Read from the game data: a divination card's stack size and reward; shards and splinters that combine into their item at a full stack; and essences and oils, where three of one tier sell to a vendor for one of the next (tiers come from the item IDs). Chains are followed up to three steps — nine of one tier for one of the tier two above. Each is compared with its result at fair value, and again "in a hurry" (buy the inputs in the dearer market, sell the result in the cheaper one). Try a recipe once in game before buying in bulk.

**Card sets whose reward is not on the exchange.** Many cards turn into a unique, a skill gem or a base type, which the exchange does not trade. For those, the cards are still priced from the exchange, but the reward's price comes from poe.ninja's stash listings: the listing with the same name, and for gems the level, quality and corruption the card text gives (a card that names no level gives a level 1 gem). Six-link and foil copies are skipped, and corrupted uniques are priced as uncorrupted because poe.ninja does not list them apart; when the exact variant has no listing, the most-listed one is used and the row says so. These rows are marked "reward priced by poe.ninja (stash listings, not the exchange)" and show how many listings back the price and how old it is. A listing price is weaker evidence than trades, so there is no "in a hurry" figure, and these prices never enter fair value, round trips or alerts. Wherever the exchange trades the reward, the exchange price is used. The desk asks poe.ninja only for the lists the card rewards need (the six unique lists, skill gems, base types), each at most once an hour, from the background sync; if poe.ninja cannot be reached, the last answer is shown and marked stale. Turn this off with `python -m vaalstreet ninja off` (the `ninja_prices` setting; `ninja on` turns it back on).

**Your own recipes and vendor prices.** No source the desk may read lists recipes or what NPC vendors sell, so the desk ships none beyond those above and lets you type in the ones you know: a recipe (say, 3 of one item and 1 of another make 2 of a third) or a vendor price (a vendor sells an item for 5 of a currency). They are kept with your ledger for every league. Your recipes are priced exactly like the built-in ones; vendor prices become swaps in round trips. Every conversion and round trip shows whether you marked it confirmed or failed in game, or still unchecked, and anything you typed in starts unchecked. Changing a count makes a new entry that starts unchecked again.

**Baskets.** A basket is a list of items with counts that you name and keep: what one map run uses, a crafting kit, what a character needs each day. You paste the list in the same formats as a stash list, see what every line was read as and which lines were not, and only then save it. Baskets are kept with your ledger for every league and priced in the league you are viewing, on the Arbitrage page. The cost now is given two ways: at fair value, and buying each item in whichever of its Chaos and Divine markets sells it for less right now, counting only a market that trades steadily (the Divine market's price is converted at the current Divine price; an item that trades steadily in neither is counted at fair value there). An item with no price in the league stays in the basket, is named, and is left out of both totals rather than counted as zero. The chart is the basket's cost at fair value for every hour of the league's last 30 days on disk, the hours an item's own chart can show: each hour adds up the units times each item's fair value at that hour, so like fair value it uses nothing published after the hour. It starts at the first hour every priced item has a fair value, and the 24-hour and 7-day changes are measured as the Markets table measures one item's.

**Round trips.** Some items trade directly for each other in small side markets. The desk walks every path of up to three swaps — buy A, swap for B (then C, then D), sell — at the rates those markets typically traded at over the last day. A path never visits an item twice. A swap whose rate is more than three times off what the two items' own prices say is left out, and so is a Divine stop for an item whose Divine market is more than three times off its Chaos market: in thin markets that is joke trades (one Vaal Orb "fetching" five Orbs of Scouring every hour), not a trade you can repeat. They are thin, so each path also shows what went through its thinnest market in a day, counting the market you buy the first item in and the one you sell the last item in as well as every swap, and the value of orders resting at its thinnest swap in the latest hour — whether the swap can be taken now or needs an order of your own. A trip that starts with a card trading one unit every few hours is only as deep as that card's market, however busy the swaps after it are.

Two more kinds of swap can join a path. One goes through Divine: sell A for Divines in A's Divine market and buy C with them in C's. That only pays when A's Divine market is dearer than its Chaos market by more than C's is, so the items on either side of Divine are bought or sold in their Chaos markets, and a path through Divine is shown only when it beats selling A for Divines and stopping there (that is already a cross flip). Divine markets are deep, so to keep them from crowding out the side markets only the best Divine path is shown for each item you start with and each item you buy with the Divines. The other is a vendor price you entered: it works one way, at any volume, so it adds no limit of its own to a path's depth.

**Trade check.** Type an offer you see in the order window — the item, the market, whether you would buy or sell, and the ratio with the items first ("64 items for 1 Divine") — and the desk answers go, caution or no-go. The offer is judged against the value of *its own market*, because the Chaos and Divine markets of an item are different prices; a Divine-market ratio is converted to Chaos at the current Divine price. A buyer gets "go" when the price is under that value by more than the model's uncertainty (never less than 2%, since whole-number ratios and Gold fees eat that much), and "no-go" when it is over by as much; a seller the other way round; in between is "caution". A market that traded in fewer than a quarter of the last day's hours, or not in the last six, never gets more than caution. The answer also shows the offer against the item's overall fair value and range, whether it beats, matches (within 4%) or misses the flip plan's order for that side and market, the market's volume per hour, and how many hours of that volume the stock on offer is.

**Ratio helper.** The exchange takes only whole numbers on both sides, so a price like 9.5 Chaos each has to be typed as "19 Chaos for 2" (buying) or "2 for 19 Chaos" (selling). Under "Ratio helper" in the check card, type the price per item in Chaos or in Divines and the desk gives the ratio, the exact price it states and how far that is from what you typed. It rounds the way flip plans post their orders: the smallest ratio within 2% (see "Whole lots"). Next to it are a rounder ratio, in smaller lots but further off ("10 for 1", 5.3% over), and up to two closer ones in bigger lots. Under one Chaos or one Divine the currency is the small side: 0.05 Divine each is "1 Divine for 20". The lots buttons scale both numbers together, and "I hold" and "I can pay" keep the ratio and the lots within what you have; a ratio whose one lot needs more than you hold is not offered. Each number has a copy button, and "Check this offer" moves the ratio into the check above. `vaalstreet ratio 9.5` does the same on the command line.

**Where an offer sits.** Under the verdict, the check shows a short ladder of prices, dearest on top: the Divine market's price, the item's fair value with its low and high, the Chaos market's price, the flip plan's sell order and buy order in the offer's market (when there is a plan), and the offer itself, marked in gold, with how far it is from its own market's price. Prices follow the top bar's Chaos/Divine switch. A market that barely trades has no row, rather than a price of zero. `vaalstreet check` prints the same ladder as text.

**Parts of a Divine.** Prices under one Divine are paid in Chaos. Click the Divine price in the top bar, or in the hideout window, to see 0.1 to 0.9 Divine in whole Chaos, with a converter that works both ways: type Chaos to read Divines, or Divines to read Chaos. It uses the Divine price the top bar shows, so during a rehearsal it follows the practice hour. Esc or a click outside closes it.

**Search string.** "Copy search string" on the Flips page's session plan, and on the Markets page with "Watchlist only" ticked, builds a text to paste into the game's search box that finds those items and no others, in the form `^(.*Alchemy|Chaos.*|Deafening.Essence.of.Greed)$`. Each item gets the shortest piece that matches it and no other item the league trades: the end of its name (`.*Alchemy`), the part after " of ", the start of its name, or else the whole name with every space and mark turned into a dot. `.*Greed` is used only when no other Greed essence trades. The pieces are packed into as few strings as fit a length limit of 200 characters, and any item too long even alone is named. Checked in game in November 2026: the exchange's item picker and the stash's search box both take this form, and a string of 200 characters worked in both. Longer strings are untested, so the limit is a number you can change.

**Stash.** Enter what you hold, or use the positions your recorded trades add up to. Each line is valued at fair value with a low and a high, and at the Chaos market's and the Divine market's own prices, so you see which market pays more and by how much. Each line also says how many hours of that market's volume it is; above three hours, selling it all at that price will push the price. The total's low and high add up every line's low and high, which assumes every price is wrong in the same direction at once — wider than the truth, on purpose. The stash you enter is kept in your ledger file. Each line shows when it was last counted: typed, pasted, or copied in game with the stack check. Copying a stack again and finding the same count also counts. What you looted or sold since then is not in the line, so sort by "Counted" to see which lines to count again.

**Pasting a list into the stash.** Typing every line is slow, so "Paste a list…" on the Stash panel takes the whole list at once, typed, copied from a spreadsheet or read from a text or CSV file you choose. Write one item per line, with the count and the name in either order: `45 Screaming Essence of Greed`, `Divine Orb 12`, `Divine Orb: 12`, `Orb of Alchemy x300`, `2,448 Portal Scroll`. In a row copied from a spreadsheet, the first cell that is text is the name and the first cell that is a number is the count. Empty lines and lines that start with `#` are skipped. "Read the list" writes nothing: it shows what each line was read as, the units your stash holds now for that item, and every line it could not read with the reason (a name that does not trade in the league comes with the closest names). Two lines for the same item count as two stacks, and their counts add. Only "Write" changes the stash, and all lines are written together or none. The list sets the lines it names and leaves every other line alone, unless you tick "The list is my whole stash"; then the lines it does not name are removed, the preview lists them first, and the desk refuses to write while any line is unread, because the item on that line would be removed. A file you choose is read by the page in your browser and goes nowhere else. `stash import <file>` does the same from the command line: it prints the preview, and writes only with `--yes`.

**Selling the stash.** "How to sell it" on the Stash panel turns what you hold into sell orders: for each line, the market to sell in, the order to post ("19 for 2 Divine"), how many to post, what it brings in and about how long it takes. It works the same for what you entered and for your ledger positions. The price is a flip plan's sell level, not a discount from fair value: the price that a given share of the last two days' volume in that market traded at or above. One control picks that share, from "sell faster" (50%: a lower price that half the volume reached) to "hold out for more" (15%); it starts at 35% and the page remembers your choice. Each line is planned in its Chaos market and its Divine market apart, and the plan recommends the one that brings in more for the line, with the other shown next to it. A market that does not trade steadily, as in the table above, gets no order. The order is a whole-number ratio, as for flips, that the units you hold can fill: someone holding 3 cannot post "26 for 1 Divine", and the line says so. With only a few items, whole numbers cannot always state the price exactly. The order then asks a little less, never more, because an order above its price would not sell at the pace the plan shows; the line says by how much ("asks 8% under the plan's price"). If the nearest order would give away more than 10%, that market gets no order. You post whole lots of the ratio, and the line says how many are left over; a market whose lots leave many unsold can bring in less than one that pays a little less for each. The time is the units posted divided by what your share of the trade at that price sells in an hour: the share your own orders measured for that item and market, or 10%. Where that would not sell it all within the two days the price was read from, the line says "thin market". "Skip lines worth less than" leaves small lines out, and the panel always says how many it left out and what they are worth at fair value. The totals show what the plan brings in next to what the planned lines, and the whole stash, are worth at fair value. "Posted…" on a line records the sell order in your ledger, as on the Flips page, and the line then says how many you posted. `stash --plan` prints the same plan, with `--reach` and `--min-value`.

**Saving your records as CSV.** "Export" in the header of the Trades, Positions, Orders, Items you made and Stash panels on the Ledger page saves that table as a CSV file for a spreadsheet. The file has the same rows and numbers as the page, all of them rather than the latest 200, and the Orders file includes orders you cancelled or collected. Times are in UTC, prices and values in Chaos. The file starts with a byte order mark so that Excel reads the item names right, and a note that starts with `=`, `+`, `-` or `@` is saved with an apostrophe in front, so a spreadsheet shows it as text and never runs it as a formula. During a rehearsal the files hold your practice records, and their names say `practice`. `export trades` (or `positions`, `orders`, `made`, `stash`) does the same from the command line, printing the table, or writing it to a file with `-o FILE`. The file is saved on your computer; nothing is uploaded.

**Small bankrolls.** The exchange trades whole lots: "64 decks for 1 Divine" cannot be sold by someone holding ten decks. Enter your bankroll and every flip is re-cut to whole-number orders that purse can post, its margin recomputed from the prices those orders really state. A small purse may fit no ratio within 2% of a level, and then posts the closest one it can: 10 Chaos cannot post the "15 for 8" a 1.9 Chaos level needs, so it posts "2 for 1", and the margin shrinks to what those orders state. Plans whose margin falls below the minimum are dropped, as are plans that cannot be run, and below the price of one Divine everything stays in the Chaos markets. The Arbitrage page filters to conversions and round trips the bankroll can start.

**Bankroll ladder.** `ladder` runs all of that at a series of purse sizes: 25, 50, 100, 200 and 400 Chaos, then 1, 2, 5 and 10 Divines at today's Divine price, sorted by what they are worth in Chaos. For each step it shows how many flips, conversions and round trips that purse can start, what opens up that the step below could not run (for example, "Divine-market flips open at 2 Divines" when one lot there costs about 285 Chaos), and three figures for the session plan, in Chaos per hour: what the same plans made over the last week against holding Divines, what they made in Chaos, and what today's levels promise. The last-week figures replay each plan at the stake it puts in, in whole lots, so a small purse's lots round the way they would in game. "Hours to next" divides the gap to the next step by the lower of the promise and the figure against Divines, for each plan; it is the gain over holding Divines, not the growth of your Chaos, so it is blank when nothing beat Divines last week. It also says what conversions alone could make at each step: the purse buys inputs worth at most itself every two hours, spent on the best margins first, so 25 Chaos cannot take every conversion's full flow at once. Then it plans a session from your purse: run these plans until the purse reaches the next step, then switch to the plans that fit the bigger purse. The purse grows at that same cautious rate, so the plan is a projection from last week's prices, not a promise.

**League start.** Leagues are aligned on days since their first trade. The playbook takes every item on today's league day in each past league and measures its move over the chosen horizon, in Divine by default (Chaos loses value through a league, so Chaos returns flatter everything). Every row shows the per-league outcomes and how many leagues it rests on. A league whose start is not on disk is left out rather than misaligned.

Precedents come from the same family of league, and only from leagues that have ended. The desk sorts every league into a family from its name and dates: challenge leagues; their Hardcore, Ruthless and Hardcore Ruthless versions (from the name's prefix); Standard and the other permanent leagues; private leagues; and **event leagues**. An event is a short league that starts at least a week after a challenge league and runs inside its life, as Phrecia ran next to Settlers, or one whose name says "Event". A new challenge league only starts when the last one ends, so that is enough to tell them apart without a list of past events. Challenge leagues learn only from past challenge leagues and events only from past events, so a short event does not skew what a new challenge league is expected to do.

**Launch day.** `playbook --launch` (and the League start page's data) goes hour by hour through the first 72 hours of each past league in the family. For every item it shows when its market first traded ("wakes up"), what it did first (rose or fell 5% from its first three traded hours, or stayed flat), and where it stood at hours 6, 24 and 72 against its first-day value, the volume-weighted average of the league's first day. Across leagues it gives the median of each, and how many leagues agree on the first move. With fewer than two past leagues whose first 72 hours are on disk, it says so instead of pretending to a pattern.

**When to buy Divines.** `divine-timing` looks at the Divine's daily price in Chaos in each past league of the family, finds the day it was cheapest (when Chaos bought the most Divines), and names the three-day stretch that holds the most of those days, for example "In 4 of 5 past leagues the Divine was cheapest in Chaos between day 1 and day 3". It always says how many leagues that rests on, and where today's league day stands.

**Meta shifts.** `meta` compares each item's demand, the units traded in the last 24 hours against league day 1, with the same league hours in every past league of the family. Units, not Chaos, because Chaos loses value through a league; day 1 rather than day 0, because the first day is a scramble. An item whose demand grew at least 1.5 times and faster than in any past league is a candidate for a meta shift: players are using it for something they did not before. Each row shows the growth against the past leagues' lowest, median and highest, and how many leagues that is.

**League report.** `report` writes a "state of the economy" web page for one league day to a local folder: the Divine price and its move against past leagues on the same day, the biggest movers among the most traded items with both markets' prices, the most traded items, what past leagues did next from this day and what is cheap or dear against them, meta shifts, and steady gaps against Hardcore and Standard. Sections with no data are left out. A page uses only data published up to the end of its day, so once a day is over, its page is the same whether you write it that evening or a month later. Each page is one self-contained HTML file with no scripts, no item icons and nothing loaded from elsewhere, and it holds nothing of yours: no ledger, stash, watchlist or alerts. `--all-days` writes every day of a league and an `index.html` that links them. The command never uploads anything; where to publish the folder, if anywhere, is up to you.

**Other leagues' prices.** `cross-league` puts the same item, on the same hour, next to its price in this league's Hardcore, Ruthless and Hardcore Ruthless versions and in Standard. Each league has its own Chaos, worth a different number of Divines, so items are compared in each league's own Divines, and the Chaos and Divine markets are compared separately. The Divine's price in Chaos gets its own line. Over the last week, the gap is taken per day (the median of the hours both leagues traded), and it is called **structural** when it held on at least 3 days and 12 hours, kept the same sign on 80% of the days, is at least 3%, and moves less from day to day than its own size. A gap that flips or closes is **noise**, and one that stays within 3% is **none**. Items cannot move between leagues, so a gap is not a trade: it tells you which differences are real when you read prices from another league, and which will close.

**Backtests.** One league is replayed hour by hour. Orders posted at hour *t* meet hour *t+1*.

- A resting order fills at its limit only in an hour whose average price traded through it, and never at a better price.
- A market order pays the hour's average plus slippage (default 3%).
- A fill takes at most a set share of that hour's volume (default 10%).
- A resting order also waits in line (the queue model, the default). When you post an order, the stock already on offer on your side of that market is the queue ahead of you. For a sell, that is the items on offer. For a buy, it is the Chaos bid for the item, counted in items at your price. The exchange publishes the lowest and the highest stock of each hour, and the backtest takes the lowest, because it is what rested through the whole hour. Your order fills only after that much volume has traded through your price, counting from when you posted. Moving an order to a new price sends it to the back of the queue. Making it bigger keeps its place, which flatters it a little. Once the queue ahead of you has traded, your order fills from the volume that trades through your price, still at most 10% of it, so the queue model never fills faster than the share model in any hour. Market orders do not queue and keep the 10% share. The exchange does not explain the stock figures, so this is a guess: if they count orders at every price, the queue is too long for a sharp price; taking the hour's lowest, and treating unknown stock as none, can make it too short. Strategies that move their prices every visit, like `swing`, rejoin the back each time. The Flips page's "Last 7 days", the session plan and the bankroll ladder use this model too.
- The older share model (`--fill-model share`, or "Share of volume" in the Backtest lab) skips the line: your order takes its share of the hour's volume from the hour it goes up, as if no one were ahead of you. It can look far better. On Mirage, `swing` beat holding Divines by +962% with the share model and trailed it by 10% with the queue model; on Allflame it was +651% against +12%. The queue model never fills more than the share model in any one hour, but over a whole run it can still end ahead on some items, because filling later changes what the strategy does next.
- Neither fill model has been checked against real fills yet. Your own tracked orders are how to check it: `fills` shows how fast the orders you recorded actually filled, and the share of the flow they took.
- A backtest trades the league's 150 most traded items, ranked by the Chaos value each has traded so far. An item joins at the first hour its value traded since the league started ranks among the top 150, and it stays from then on, so you can always sell what you hold. Before it joins, the strategy can neither see it nor trade it. Earlier versions ranked items by their value over the whole run, so on day one a backtest already traded the items that would only take off in week three.
- No leverage and no shorting. Sizing is on a fixed bankroll unless you ask to compound. A buy that finds no cash left does not count as a fill. Earlier versions counted it, so fill counts of runs that ran out of cash are lower now; their profit is the same.
- Every result shows its return, what the same Chaos made held in Divines, and **Vs Divines**: the return measured in Divines, (1 + return) ÷ (1 + Divines' return) − 1. Judge a strategy by that last one. In the first 7 days of Covens, the `swing` strategy made +94% in Chaos while holding Divines made +125%: −14% against Divines.
- `attention` is how many hours pass between your visits; orders stand in between.
- A play schedule (`--schedule "mon-fri 19-22"`) limits your visits to the hours you actually play. Times are UTC, and the end hour is not included, so that example is three hours each weekday evening. A visit happens when an hour's prices come out, which is when that hour ends. Inside a session, `attention` still sets how often you come back. Your orders keep standing between sessions.
- Whole lots (`--whole-lots`) make the backtest trade like a real purse, with the same orders the Flips page posts. Each order becomes the smallest whole-number ratio within 2% of its limit that your cash can pay for, like "10 Chaos for 3" for 3.31 Chaos. It is rounded either way, so a buy can state up to 2% more than its limit and a sale up to 2% less; it fills only in whole lots, and at the price that ratio states, not at the limit. On the Flips page, the last-week replay of each session-plan pick at its stake runs this way too; the 1,000 Chaos replay shown for every plan does not. An order you cannot afford even one lot of is never posted. When your cash, or the items you hold, fit no ratio within 2% of the limit, the order takes the closest ratio that fits, and is not posted if that ratio would pay more than 2% above a buy's limit or ask more than 2% below a sale's: with 3 Chaos, a buy at 2.3 posts "2 for 1", but with 5 Chaos it is not posted as "5 for 2", which would pay 2.5. The `swing` strategy never offers its items below what they cost plus its minimum margin, and with whole lots it holds to that on the price the order states: a 2% flip that would round to selling at cost is offered one step higher instead. A Divine-market order states whole Divines, so what it costs in Chaos moves with the Divine price until it fills. Market orders fill whole items.
- Several strategies can share one bankroll (`--portfolio`). Each one sees only its own items and orders, and sizes its orders as if the bankroll were its own. They compete for the same Chaos, the same Gold budget and the same share of each hour's volume. Conflicts are settled in the order you list them: every hour the first strategy's orders fill first, and the next ones fill from what is left. The result shows the total and each strategy's profit, its share of the profit, its Gold, and the most and average Chaos it had tied up in items.
- Every run also measures the risk of what you hold. Each hour, it values your items at fair value and works out the **worst drop**: what your holdings would lose on a bad day for these items, about 1 day in 20. A bad day comes from how much each item's fair value moved hour to hour over the last 7 days, stretched to how long you expect to hold (`--risk-hours`, default 24). The result shows the most you held, the worst drop at any hour and the average one over the run. It assumes every item has its bad day at once, which overstates a calm market, and a crash can do worse than a 1-in-20 day. For an item's first half day of prices the drop counts as zero.
- You can share a strategy (`--export file.json`). The file holds the strategy, its settings, the backtest options, the result for every league you ran, the desk version and, for your own strategy file, its code. Nothing is uploaded; passing the file on is up to you. `strategy import file.json` shows what a file holds. A file with code shows that code under a warning, because the code runs on your computer with your permissions when you backtest it. It is saved to the `strategies` folder only when you add `--yes`, and never over an existing file.
- **Strategy search** (`search swing --grid 'reach=0.2,0.3;top=20,40'`) tries every combination of the settings you list, and the run options attention, schedule, whole lots, fill model, participation, slippage and Gold per unit, up to 200 combinations. It judges them the way you would have used them at the time. The leagues are put in order of their start. Each league is tested with the setting that did best on the leagues that had already *ended* before it began, so a league still running at its start, such as Standard or the tail of the previous league, is never used to choose. The report shows, for each tested league, the chosen setting's result there next to the strategy's default settings and holding Divines, the average over those leagues, how many settings were tried and how often the choice changed from one league to the next. The best result on the earlier leagues is shown only as "fit on earlier leagues": it is the best of many tries, so it flatters. The score it maximises is the return over holding Divines by default (`--score return` for the Chaos return, `--score drawdown` for return over the worst drop). A schedule contains commas, so give the grid as JSON for it: `--grid '{"schedule": ["sat,sun 10-14", "mon-fri 19-22"]}'`. Each setting runs once per league; on a two-week league a run takes a few seconds, so a large grid over many leagues can take a while. `--export` saves the setting it would pick for the next league, with the table.
- Gold (`--gold-per-unit`, `--gold-budget`) is charged for every unit you post. Moving an order to a new price or making it bigger is a new post and costs Gold again. Leaving it alone, or letting it shrink, costs nothing. Gold is not refunded on cancel (confirmed in game), so a cancelled order's Gold stays spent. Once the budget is spent, no new orders go up, but orders already standing can still fill. The result shows the Gold spent and the Chaos earned per 1,000 Gold.

**Alerts.** Alerts are checked once an hour, when a new hour's prices arrive. A price alert fires when a value crosses your threshold. A flip-plan alert fires when a plan for your item, or for any item, reaches your margin and profit per hour. A round-trip alert fires when a round trip reaches your edge and the orders waiting at its thinnest swap are worth at least the Chaos you set, so there is something to take right now. An order alert fires when one of your recorded orders should be re-priced, cancelled or collected. A league alert fires when an item is cheaper or dearer than on the same day of past leagues by your percentage, or when past leagues moved it by at least your percentage over the next days. An alert rings once when its condition starts. It rings again only after the condition has gone away and come back, and never twice for the same thing within 6 hours, so a price hovering on your line does not ring every hour. Each alert writes a short title that can be read aloud, such as "Test Orb filled, post the sell".

**Wealth over time.** The Ledger page charts what you hold over time, from snapshots. A snapshot records, for one league, both pictures the desk has of what you hold: the stash list you entered and the positions your recorded trades add up to. It keeps every item's units and its fair value at that hour, the worth of each picture (the same total the Stash panel shows), the profit you had realised so far and that hour's Divine price. Each snapshot is valued once, at the hour it was taken, and never again, so a later price never changes an earlier point; an amount shown in Divines uses that snapshot's own Divine price. While the desk runs, it takes one snapshot after each new hour of prices for every league where you hold something, at most one per league and hour; you can turn that off with "Take one every hour". "Snapshot now" takes one at once, with a note if you like, and ✕ deletes one. The desk keeps its own snapshots hourly for 30 days and then keeps only the last one of each day; the ones you take are never removed. The chart shows your worth and a second line, "had you held Divines instead": the worth at the first snapshot shown, turned into Divines at that hour's price and held. Snapshots pause during a practice run, which has no wealth of yours to chart.

**What changed between two snapshots.** Under the chart, pick two snapshots (the first and last in the range shown, unless you choose others) to see what changed, item by item: the units then and now, the change, and what that change is worth at the later snapshot's price, in two lists, Gained and Lost, each with its total. The change in your worth is split in two parts that add up to it: "you hold more or less" is the change in units at the later snapshot's prices, and "prices moved" is the units you held at the earlier one times how far each price moved. If you held 10 orbs at 2 Chaos and now hold 15 at 2.5, you hold 5 more, worth 12.5, and the prices moved your 10 by 5, so your worth went up 17.5. An item with no price at one of the two snapshots is listed apart as "no price then" and is not counted as zero. The panel also says how long passed between the two and the change per hour. It works for either picture. For the stash list it also measures a farming session, which the ledger cannot see: take a snapshot before you start mapping and another when you stop, and what you looted shows under Gained. Each snapshot also keeps the price of the items you held earlier but no longer hold, so a sale between the two is valued at the later price too.

### What the model cannot see

Read flip and backtest figures as a ceiling, not a forecast.

- **Gold.** Every order costs Gold, and the fee schedule is not published. The desk does not guess it: it learns the Gold per item from the trades and orders you record in the Ledger (the middle value of your records), and shows the fee as unknown until you have recorded some, unless you enter an assumed fee yourself. Fees can differ by item and market in ways your records do not show, and what a swap between two items costs is assumed, not known. Backtests charge a Gold fee per unit that you choose, because the real fee for each item is not known to them. Gold is often the real limit on how much you can flip, which is why plans can be ranked by Chaos per 1,000 Gold.
- **Queue position.** Orders at the same ratio fill in time order. The desk shows how many hours of volume already rest on each side, but cannot know where you would stand. Backtests and the desk's replays put your resting orders behind the stock already on offer on your side, a guess at your place from the published stock, which may count orders at worse prices than yours. No one has checked yet how close that guess comes to real fills; your own tracked orders (`fills`) are the way to check it.
- **Hourly granularity.** A level is counted as reached only when the whole hour's average traded through it, which is conservative; the path inside the hour is unknown.
- **Small samples.** There have only been a handful of leagues since the exchange launched. League-start patterns are precedents, not odds.

Check the in-game order book before committing size.

### Your own strategy

A strategy is a class with `step(ctx)`. It sees only what was published up to the current hour.

```python
# examples/cheap_vs_divine.py (shortened)
import numpy as np

class CheapVsDivine:
    """Buy liquid items under fair value in the Chaos market, offer them 8% up in the Divine market."""

    def step(self, ctx):
        if ctx.t < 48:
            return
        traded = np.nansum(ctx.history("value", 48), axis=0)
        liquid = traded >= np.sort(traded)[-30]
        fair = ctx.fair
        units = np.where(liquid, 0.03 * ctx.bankroll / fair, 0.0)
        ctx.quote_buys("r", np.where(liquid, fair * 0.96, np.nan), units)       # "r" = Chaos market
        ctx.quote_sells("b", ctx.average_cost * 1.08, ctx.position)             # "b" = Divine market
```

```sh
python -m vaalstreet backtest examples/cheap_vs_divine.py:CheapVsDivine --league Allflame
python -m vaalstreet backtest examples/cheap_vs_divine.py:CheapVsDivine --params '{"markup": 0.12}'
```

`ctx` offers `fair`, `z` (how surprising this hour's print was), `history(column, hours)`, `swing(leg, reach)`, `position`, `average_cost`, `cash`, `bankroll`, `whole_lots` (whether the run trades whole lots), `stated_sell(leg, limit)` (the price a sale at that limit would really state, after whole-lot rounding), and `quote_buys` / `quote_sells` / `buy` / `sell`. Built-in strategies (`hold`, `swing`, `reversion`, `momentum`) are in `vaalstreet/backtest.py` and are short enough to read as examples.

## Screen check (optional)

Instead of typing an offer into `check`, you can press a key while the Currency Exchange window is open. A small companion program takes one screenshot, reads the two items, the ratio, the amounts you typed and the Gold off it, and asks the desk for its go / caution / no-go verdict. The verdict appears in the companion's console and as a desk event, so the hideout window shows it and, if you turned that on, reads it aloud ("Go: Orb of Alteration at 0.6, 5% under the market").

**GGG's rule, in plain words.** A tool may read the screen only once each time you press a key, and you must know what it reads. So the companion takes exactly one screenshot per press, never on a timer, and ignores presses while it is still busy. It sends nothing to the game: no keys, clicks, chat or mouse moves. It never reads game memory or game files. The screenshot stays in memory and is thrown away after the check; nothing is saved to disk. Every verdict starts with what was read ("Read: buy 64 Orb of Alteration for 1 Divine"), so check that line: a misread digit gives a confident wrong answer.

**What it reads.** The rectangle you set (or your whole main screen), looking for the exchange window's "I Want" and "I Have" labels, the two item names on the row under them (the wanted item is the left one), the amounts you typed either side of the ratio, and the Gold shown above "Place Order". The offer it checks is your own when you typed both amounts (13 for 43 is judged as 13 for 43), else the ratio the window suggests. If it is not sure of a part, it says so and asks you to press again or type the offer with `check`, rather than guessing. The layout was read from the live game in November 2026 on a 2560 x 1440 screen in English. The whole screen works and is the easy choice, because the window moves when the stash or inventory opens; a rectangle only makes a press faster. Text from other things on screen (minimap names, the desk's own page) is ignored unless it stands where the window's own text should.

**Install on Windows.** The companion must run under Windows Python, next to the game: a Python inside WSL can neither see the Windows screen nor hear Windows key presses. Use Python 3.10 to 3.12 (the text-recognition library has no build for 3.13 yet). The package is not on PyPI, so install it from a copy of this repository on the Windows side (clone it there, or copy the WSL checkout). In PowerShell or cmd, inside that folder:

```
py -3.12 -m venv .venv-screen
.venv-screen\Scripts\activate
pip install -e ".[screen]"
```

This installs the desk's three libraries plus `mss` (screen capture), `pynput` (the hotkey; it works without administrator rights, unlike the `keyboard` library on some systems, and is maintained) and `rapidocr-onnxruntime` (text recognition with its models inside the package, so nothing is downloaded when it runs and no separate program such as Tesseract is needed). Use double quotes: cmd does not understand single ones.

**Or run both together on Windows.** When the desk's data is on the Windows side too, one command runs the desk and the screen check in one process, with nothing in WSL:

```
python -m vaalstreet app            # the desk at http://localhost:3000 and the screen check; Ctrl+C stops both
python -m vaalstreet app --stash    # the same, with the stack check writing copied stacks to your stash list
```

The screen check starts once the desk has market data (on a first start, after the first download). If its libraries are not installed, the desk runs alone and says so. `--no-screen` runs the desk alone on purpose, and `--hotkey` and `--record-hotkey` change the keys.

**Run it next to the desk in WSL.** Start the desk in WSL as usual (`python -m vaalstreet serve`). WSL2 passes `localhost` through to Windows, so on Windows run:

```
python -m vaalstreet screen --calibrate                    # optional: read a rectangle in place of the whole screen
python -m vaalstreet screen --desk http://localhost:3000   # press Ctrl+Alt+F9 in game; Ctrl+C here to stop
```

**Stack check: what is this stack worth?** Start the companion with `--stacks`, hover a stack in your stash or inventory, and press the game's own copy key, Ctrl+C. The game copies the item's text to the clipboard; the companion reads it once and asks the desk what the stack is worth. The answer appears in the companion's console and in the hideout window ("2,448 Portal Scroll: 12 Chaos, 16% more for Divines"): the worth at fair value with its low and high, which of the item's two markets pays more and by how much, and how many hours of that market's volume the stack is, with a warning when selling it all would push the price. With `--stacks` alone nothing is saved: your stash list on the Ledger page is not changed.

**Filling your stash list by copying.** Start the companion with `--stash` instead, and each stack you copy is also written to the stash list, so you never type it. A copy sets the item's line to the count it read, and says what it replaced ("Stash: Portal Scroll set to 2,448. It replaces the 2,000 the list held."). The copied text does not say where a stack lies, so the companion goes by two things. First, the size of a full stack, which the game prints after the slash ("2,448/40"). A count above it can only be the pile in a tab with one space for the item, such as the currency tab. A pile always sets the line and never adds, so the loot you drop into it while playing maps, or what an order takes out of it, never doubles the count: copy the pile again and the line is right. Second, for counts up to a full stack, the copy just before: the same item again with a different count is another stack and adds ("Stash: Chaos Orb 2,448 + 12 = 2,460 (another stack)"); the same item with the same count is the same stack pressed twice and changes nothing. "Just before" means within two minutes. So count the pile first and loose stacks after it. What stays wrong, so check the sum the console prints: two stacks of one item with exactly equal counts, copied one after the other, count once; a stack of up to a full stack, copied twice within those two minutes with its count changed in between, is added to itself; two piles of one item in two tabs count as the later one; and a loose stack copied before the pile is dropped when the pile is copied. To start an item's count over, copy another item first, or edit the line on the Ledger page. The list is only as fresh as your last copy of each item: loot you have not copied since is not in it. During a rehearsal the copies go to the practice stash, and the console says so. A misread now changes your list, not only a line in the console, so try `--stacks` in game first. That a count above a full stack means a one-space tab comes from how other tools read the copied text; it has not been checked in game.

**Seeing what the screen check read.** After each press, read or not, the companion tells the desk the lines of text the recognition returned and what it understood ("buy 64 Orb of Alteration for 1 Divine") or why it could not. The Ledger page shows the last ten under "What the screen check read", and the hideout window the last three. Each reading is one line; open "What it saw" under it for the recognised lines in a fixed-width face, to see a misread digit or name, and "Copy the lines" to paste them somewhere. A copied stack shows only its name and count; the copied text itself is never sent. The desk keeps these in memory only: nothing is written to disk, and they are gone when the desk restarts. The screenshot never leaves the companion. When the recognition keeps misreading an item's name, click the line and say which item it means ("when it reads Orb of A, it means Orb of Alteration"). The desk keeps these corrections in your ledger, for every league and also during a rehearsal, and the companion uses one only for exactly that text, from its next press; a text that only looks like it still has to match a name closely. The list under the readings shows them, with ✕ to delete one.

**Recording the order you are placing.** Under each reading the desk understood, "Posted this order…" opens the same form as a flip plan's "Posted…" button, with the item, the side and the market filled in. The ratio and the count come from the amounts you typed either side of the ratio when the screen check could read both without doubt (reduced to the smallest whole numbers, so 40 for 380 Chaos is posted as 2 for 19, 40 in all). Otherwise the form takes the flip plan's order for that item and market, or failing that the market ratio it read, which is the market's suggestion and not your order; it then says so, lets you change the ratio, and leaves the count for you to type. Nothing is recorded until you press Record, and nothing is sent to the game. The amounts are read only in the window's own shape: one whole number on each side of the ratio, between the two item names; anything else gives no amounts. The amount fields are small, so the companion looks at that row a second time, enlarged, and at a field by itself when it is still unread. Only amounts you typed count: the grey numbers the game suggests in empty fields are told apart by their brightness and ignored. The two amounts must also give the ratio the window shows between them, so a misread digit gives no amounts and never a wrong order. The Gold the window showed is filled in too.

**Recording with a key, without clicks.** A second key, Ctrl+Alt+F10, reads the window in the same way and also writes the order it shows to your Ledger: the item, the side, the market, the amounts you typed and the Gold. Press it when you post the order (the amounts stay in the window after "Place Order"). The companion says what it recorded ("Recorded in your Ledger: buying 13 Stacked Deck for 43 Chaos, 455 Gold"), and the reading on the desk is marked as recorded. It records nothing unless it read an amount on both sides, and the same order read again within a minute is not recorded twice. You still post the order yourself; nothing is sent to the game. If you pressed it without posting, delete the order under Orders on the Ledger page. Change the key with `--record-hotkey`. The game's list of your open orders shows icons, not names, so the desk cannot read your orders' fills from the screen; you record those with "Filled…".

It is off unless you ask for it, and it follows the same rule as the screenshot. You press the key yourself, and the companion sends none. It reads the clipboard once per press, and only while the game is the window in front, so a Ctrl+C in your browser or password manager is never read. It waits up to half a second for the game to copy, by watching Windows' count of clipboard changes, which says nothing of the contents; if the game copied nothing, it reads nothing and says so. Text that is not a copied item is dropped: never shown, never sent to the desk. Only the item's name and the size of the stack reach the desk. Every answer starts with what was read ("Read: 2,448 Portal Scroll"). The game must run in English, and the stack check works only under Windows Python. If a Ctrl+C in game seems to do nothing, add `--why`: the companion then says when it heard the key but ignored it because another window was in front, and names that window's kind ("Chrome_WidgetWin_1" is a browser). It still reads nothing in that case. It was tested against the live game in November 2026.

The default key is Ctrl+Alt+F9, chosen to stay clear of the game's own keys (Ctrl+Alt+C copies an item); change it with `--hotkey "<ctrl>+<shift>+<f8>"`. The game still sees the key press, so pick a combination the game ignores. Run the game in windowed or borderless windowed mode so the screenshot shows it. If you run the game as administrator, run the companion as administrator too, or Windows hides your key presses from it. The rectangle is saved in `screen.json` in the data directory of the Windows copy (`data\` in a checkout); the companion never opens your ledger or the archive.

```
data/rehearsal.sqlite                      practice trades from the last rehearsal; emptied when a new one starts
```

To move the archive to another machine without downloading it again, `python -m vaalstreet snapshot <folder>` packs the indexed history into 9 MB parts, and `python -m vaalstreet restore <folder>` rebuilds it from them.

Other settings: `PORT` (default 3000) and `POE_USER_AGENT` (the identification string sent with every request; by default `vaal-street/2.0 (+https://github.com/roelschr/vaal-street)`). The server binds to `127.0.0.1` and refuses requests from other sites.
